# PIXEL SHOP // PORTFOLIO

Одностраничное портфолио в виде ночной пиксельной витрины. Проект не требует сборки: это чистые HTML/CSS/ES-модули и относительные пути, поэтому его можно разместить на GitHub Pages.

## Локальный запуск

Откройте папку через любой статический сервер, например:

```bash
python3 -m http.server 3000
```

Затем перейдите на `http://localhost:3000`. Открытие `index.html` напрямую через `file://` не рекомендуется: браузер может заблокировать ES-модули.

## Supabase

Создайте новый проект на [supabase.com](https://supabase.com). В Supabase SQL Editor выполните сначала `supabase/schema.sql`, затем `supabase/seed.sql`. Схема создаёт категории, работы, изображения, реплики, контакты, настройки, RLS и публичный Storage bucket `portfolio`.

В Supabase Auth создайте пользователя администратора через Authentication → Users. Пароль `1965` поддерживается по запросу, но это слабый пароль: для реального сайта замените его на длинный уникальный пароль. После создания пользователя получите его UUID и выполните:

```sql
insert into public.admin_profiles (user_id)
values ('UUID_ПОЛЬЗОВАТЕЛЯ');
```

В `config.js` можно вставить Project URL и anon public key из Settings → API. После обновления интерфейса те же значения можно сохранить прямо в админ-панели, в блоке `SUPABASE SETTINGS`:

```js
window.PORTFOLIO_CONFIG = {
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR_ANON_PUBLIC_KEY'
};
```

Никогда не вставляйте `service_role` key в этот файл. RLS разрешает публичное чтение портфолио, а запись и удаление — только пользователю, который есть в `admin_profiles`. Storage bucket читается публично, но загрузка и удаление доступны только администратору.

## Управление

На главном экране наведите курсор на объект, чтобы увидеть печатающиеся название и реплику персонажа. Клик открывает категорию. На карточках со множеством фото стрелки листают изображения без открытия, клик по карточке показывает только выбранную фотографию на полном экране; каталог остаётся позади с размытием. Тройной клик по персонажу открывает вход в админ-консоль. В интерфейсе входа показывается только поле пароля: email администратора берётся из внутреннего `adminEmail` в `config.js` и не запрашивается у пользователя. В консоли можно добавлять работы и несколько фотографий прямо с устройства через `input type="file"`, удалять работы, добавлять и редактировать контакты (название, значение и ссылку), а также управлять репликами.

## GitHub Pages

1. Создайте репозиторий и скопируйте в него содержимое этой папки.
2. Проверьте, что `index.html` находится в корне репозитория.
3. В Settings → Pages выберите Deploy from a branch, ветку `main` и папку `/root`.
4. Откройте опубликованный адрес и проверьте, что `config.js` содержит правильные публичные значения Supabase.

`404.html` и относительные ссылки оставлены для корректного поведения GitHub Pages. Не переименовывайте папки `assets`, `css`, `js` и `supabase`.
