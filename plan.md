# План реализации: пиксельное портфолио

## Исходные материалы и композиция

Все семь PNG из пользовательской папки `ASSETS` на Google Drive загружены в `assets/` и сверены по MD5. Рабочая система координат главного меню — фактический размер `maket.png`: **1280 × 832**. Фон сайта будет выводиться из `background.png`, а `maket.png` останется в проекте как референс компоновки.

Чтобы не потерять положение элементов при изменении экрана, главное меню будет рендериться как масштабируемая сцена с сохранённым соотношением сторон. Desktop-координаты, снятые с макета:

| Элемент | Назначение | Базовая область на сцене 1280 × 832 |
|---|---|---|
| `icon1.png` | Контакты | x 284, y 303, 157 × 79 px |
| `icon2.png` | Плакаты | x 584, y 285, 112 × 100 px |
| `icon3.png` | Одежда | x 228, y 427, 151 × 143 px |
| `icon4.png` | Оформление и инфографика | x 439, y 402, 169 × 171 px |
| `main.png` | Персонаж в правом окне | изображение около x 753, y 274, ширина 284 px; выводится через клип-область окна примерно x 768, y 323, 191 × 205 px, чтобы фигура корректно уходила за стойку |

На небольших экранах сцена сохраняет композицию и масштабируется целиком; у интерактивных объектов будут невидимые touch-области не меньше 44 px. Разделы работ станут сеткой 3 → 2 → 1 колонки.

## Технологический подход

* Статический SPA без сборки: чистые `HTML`, `CSS` и ES-модули `JavaScript`; все локальные пути относительные, поэтому проект можно разместить на GitHub Pages.
* `Press Start 2P` подключается с Google Fonts с системным monospace fallback. Стиль: пиксельная витрина ночью, тёплый янтарный свет, чёткие прямоугольные рамки, едва заметные scanlines и анимации на `steps()`.
* Supabase JS подключается из CDN. В `config.js` будут только публичные значения и подробные комментарии; `SUPABASE_URL`, `SUPABASE_ANON_KEY` и необязательный `ADMIN_EMAIL` пользователь вставляет сам.
* Начальные данные в `seed.sql`: четыре категории, порядок и нейтральные стартовые реплики. Контакты и портфолио-работы остаются заполняемыми через админ-панель.

## Безопасная админ-панель

Тройной клик по персонажу откроет вход в админ-панель. Для соблюдения требования «1965» без хранения секретов на фронтенде будет использован **Supabase Auth email/password**: код вводится пользователем в диалог, сразу передаётся в Supabase Auth и не записывается в JS, HTML, `config.js`, Storage или базу в открытом виде. В README будет шаг, как создать администратора в Supabase Auth, назначить запись `admin_profiles` и задать пароль `1965` (или безопасно заменить его на более длинный). RLS позволит операции записи и удаления только пользователю из `admin_profiles`; все остальные пользователи получат только публичное чтение.

> Четырёхзначный пароль заведомо слабый. Он будет реализован именно по запросу, но README предложит заменить его после первого запуска.

## Поведение интерфейса

1. При наведении каждая иконка получает лёгкий случайный сдвиг/наклон, белый glow и верхнюю пиксельную подпись; у персонажа запускается мелкое покачивание без изменения опорной позиции, а реплика выбирается случайно из Supabase.
2. Клик по иконке открывает соответствующий раздел. Карточки содержат первое фото, краткое описание и локальные стрелки галереи. Клик по карточке открывает полноэкранный пиксельный modal с увеличением, полным текстом и перелистыванием.
3. Контакты — отдельный простой раздел. Во всех внутренних разделах есть пиксельная кнопка «Назад».
4. Админка даёт табы «Плакаты», «Одежда», «Оформление и инфографика», «Контакты», «Реплики» и CRUD для работ, изображений из Storage, порядка, реплик и контактов. Изменения обновляют клиент сразу после успешной операции.
